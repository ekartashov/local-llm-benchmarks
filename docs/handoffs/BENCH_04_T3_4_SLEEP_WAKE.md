## Title
T3.4 — vLLM CPU-offloaded prefix cache survival across sleep level=1 / wake

## Objective
Determine whether vLLM's CPU-offloaded prefix cache is preserved or flushed when the server goes through a sleep level=1 / wake_up cycle. Measure prefill time before sleep (cold), immediately after a cache hit (warm), and after wake.

## Why this exists
If the prefix cache survives sleep/wake, users can pause a model and resume without re-paying the full prefill cost on the same context. If it is flushed, the first post-wake request costs a full cold prefill. This affects whether sleep mode is transparent to running conversations.

## Single variable under test
**Sleep/wake cycle** — presence or absence of one sleep level=1 + wake_up cycle between the warm-cache request and the post-test request.

The three measured states are:
1. **cold_prefill** — first-ever request, no cache
2. **warm_cache_presleep** — same prompt, cache already populated
3. **warm_cache_postwake** — same prompt, after sleep + wake

The variable is whether the cache survives the cycle (state 3 ≈ state 2) or resets to cold (state 3 ≈ state 1).

## Metrics to record

| Metric | Field path | Unit |
|--------|-----------|------|
| Cold prefill time | `metrics.cold_prefill_ms` | milliseconds |
| Warm cache prefill (pre-sleep) | `metrics.warm_cache_presleep_ms` | milliseconds |
| Post-wake prefill time | `metrics.warm_cache_postwake_ms` | milliseconds |

Derived values to note:
- Cache hit ratio pre-sleep: `warm_cache_presleep_ms / cold_prefill_ms` — expected ≪ 1.0
- Cache survival ratio post-wake: `warm_cache_postwake_ms / cold_prefill_ms` — 1.0 = full miss, ≪1.0 = cache survived

## Pass/fail checks

| Check | Pass condition | Fail action |
|-------|---------------|-------------|
| Cache hit confirmed pre-sleep | `warm_cache_presleep_ms` < 0.3 × `cold_prefill_ms` | Record anomaly; prefix cache may not be working |
| All three timings present | No null fields in `metrics.json` | STOP; write `## Open from testing` |
| Script exits cleanly | Exit code 0 | Note exact error |

There is no pass/fail for the post-wake result itself — both outcomes (cache survived or cache flushed) are valid answers to the research question. Record the number and stop.
